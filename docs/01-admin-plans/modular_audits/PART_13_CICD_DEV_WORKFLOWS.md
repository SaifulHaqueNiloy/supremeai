```md
# ADR-001: Implement Machine-Readable Schemas for Agent-to-Agent Communication

**Date**: 2026-07-12

**Status**: Proposed

## Context

Our current documentation system, including READMEs and docstrings generated by the AI Scribe, is designed for human readability. While this is excellent for developers, our autonomous AI agents within the Swarm cannot efficiently parse this information to understand how to use different tools or "skills." This creates a bottleneck for true autonomous operation and self-evolution, as agents rely on hardcoded logic or brittle parsing instead of a structured understanding of available tools.

## Decision

We will enhance the AI Scribe agent to generate a machine-readable schema (`tool_schema.json` or a similar OpenAPI-like format) alongside every human-readable skill documentation (`SKILL.md`). This schema will define the tool's purpose, input parameters (with types and descriptions), and expected output format.

The main agent orchestrator (`parallel_agent_executor.py`) will be updated to use these schemas. When delegating a task, the main agent will first consult the relevant `tool_schema.json` to correctly format the request and provide the necessary parameters to the sub-agent.

## Consequences

**Positive:**
- **Enhanced Autonomy**: Agents can dynamically discover and use tools without human intervention.
- **Improved Accuracy**: Reduces errors from incorrect parameter passing between agents.
- **Foundation for Self-Evolution**: Agents can understand the capabilities of other agents, enabling them to propose and implement more complex, multi-agent workflows, aligning with our "Autonomous Evolution" goal (Dafa 15).
- **Scalability**: Adding new tools/skills becomes more robust, as the machine-readable contract ensures seamless integration.

**Negative:**
- **Initial Implementation Overhead**: Requires modification of the AI Scribe and agent orchestrator.
- **Schema Maintenance**: Schemas must be kept in sync with tool implementations. This can be automated as part of the Scribe's generation process.

```

### 📄 `.github/workflows/cache-janitor.yml`

```yaml
name: "🧹 Cache Janitor (Auto Cleanup)"
on:
  schedule:
    - cron: '30 3 * * *'   # প্রতিদিন রাত ৩:৩০ UTC, main pipeline-এর পরে
  workflow_dispatch: {}

permissions:
  actions: write

jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      # বাংলা মন্তব্য: ৭ দিনের বেশি পুরনো বা বাতিল করা ব্রাঞ্চের ক্যাশ ডিলিট করার অটোমেশন
      - name: Delete caches older than 7 days or orphaned from closed/merged branches
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          REPO="${{ github.repository }}"
          echo "বর্তমান cache তালিকা:"
          gh cache list --repo "$REPO" --limit 100 --json id,ref,key,createdAt,sizeInBytes \
            > caches.json

          # ৭ দিনের পুরনো cache মুছে ফেলুন
          CUTOFF=$(date -d '7 days ago' +%s)
          jq -c '.[]' caches.json | while read -r c; do
            created=$(echo "$c" | jq -r '.createdAt')
            created_ts=$(date -d "$created" +%s)
            id=$(echo "$c" | jq -r '.id')
            if [ "$created_ts" -lt "$CUTOFF" ]; then
              echo "🗑️ Deleting stale cache id=$id (created $created)"
              gh cache delete "$id" --repo "$REPO" || true
            fi
          done

      - name: Report total cache usage
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: gh cache list --repo "${{ github.repository }}" --json sizeInBytes --jq 'add.sizeInBytes // 0 | . / 1048576 | tostring + " MB total"'

```
