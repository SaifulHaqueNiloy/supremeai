`origin/main` এখন আগের branch-এর চেয়ে অনেক এগিয়েছে। বিশেষ করে:

- Control-plane auth header fix এসেছে।
- Multi-node service URL wiring এসেছে।
- Health check resilient হয়েছে।
- Scraper health path align হয়েছে।
- Supabase migrations 15 ও 16 verified হিসেবে ডকুমেন্টেড।
- Render service URLs এবং frontend API URL configured হিসেবে ডকুমেন্টেড।
- Merge conflict বর্তমানে নেই।

তবে `origin/main`-কেও এখনো পুরোপুরি “production-complete” বলা যাবে না।

> গুরুত্বপূর্ণ: বর্তমান checkout এখনো `v0/wire-service-capabilities` branch-এ আছে। আমি `origin/main` fetch করে যাচাই করেছি; সরাসরি local branch switch করিনি।

# Main branch-এ ইতিমধ্যে সম্পন্ন

### ১. Control-plane authentication

`frontend/src/services/controlPlane.ts` এখন `getAuthHeaders()` ব্যবহার করছে।

এটি আগের বড় সমস্যা ঠিক করেছে:

```plaintext

```

এখন auth header ছাড়া request যাওয়ার কথা নয়।

Render service URL source code-এ হার্ডকোড না করে environment variables থেকে নেওয়া হচ্ছে।

এতে database temporarily unavailable হলে পুরো health system অযথা crash করার ঝুঁকি কমেছে।

### ৪. Scraper health path

Scraper service-এর health endpoint এবং control-plane probe path align করা হয়েছে।

### ৫. Supabase setup status

`docs/ADMIN_TASKS.md` অনুযায়ী:

- Migration 15 completed ও verified
- Migration 16 completed ও verified
- `match_experiences` RPC response করছে
- Supabase vector path সক্রিয় করার configuration documented

### ৬. Render URL setup

ডকুমেন্ট অনুযায়ী চারটি Render service-এ URL environment variables injected হয়েছে:

- `BACKEND_URL`
- `WORKER_URL`
- `SCRAPER_URL`
- `MCP_URL`

Frontend-এও `VITE_API_URL` এবং `VITE_BACKEND_URL` configured হিসেবে লেখা আছে।

এগুলো code থেকে নয়, deployment environment থেকে verify করতে হবে।

# এখনো যেসব fix দরকার

## Priority 0 — Main branch সত্যিই deploy হয়েছে কি না যাচাই

Code main branch-এ থাকলেই production-এ deployed হয়েছে—এটি ধরে নেওয়া যাবে না।

ম্যানুয়ালি verify করতে হবে:

```plaintext
Core service deployed commit = origin/main HEADWorker service deployed commit = origin/main HEADScraper service deployed commit = origin/main HEADMCP service deployed commit = origin/main HEADFrontend deployed commit = origin/main HEAD
```

Mixed revision থাকলে frontend নতুন contract ব্যবহার করবে কিন্তু backend পুরোনো contract দিতে পারে।

---

## Priority 1 — Frontend থেকে Worker direct call সরানো

এখনও `controlPlane.ts`-এ:

```plaintext
VITE_WORKER_URL
```

ব্যবহার করা হচ্ছে।

আদর্শ architecture হওয়া উচিত:

```plaintext
Frontend  ↓Core API / Gateway  ↓Worker  ↓Scraper / MCP / অন্যান্য capability
```

বর্তমান implementation আংশিকভাবে:

```plaintext
Frontend  ↓Worker direct
```

এটি security, auth, audit এবং tenant isolation-এর জন্য ভালো নয়।

### Fix

Core API-তে task gateway যুক্ত করতে হবে:

```plaintext
POST /api/v1/tasksGET  /api/v1/tasks/{id}POST /api/v1/tasks/{id}/cancel
```

তারপর Core server-side থেকে Worker call করবে।

Frontend থেকে `VITE_WORKER_URL` সরানো যাবে।

---

## Priority 2 — Capability “available” check বাস্তব করা

বর্তমান registry-তে service URL configured থাকলেই capability available ধরা হচ্ছে।

কিন্তু:

```plaintext
URL configured ≠ Service healthy ≠ Capability working
```

উদাহরণ:

- `SCRAPER_URL` আছে, কিন্তু scraper endpoint fail করছে
- `MCP_URL` আছে, কিন্তু MCP tool discovery fail করছে
- Worker alive, কিন্তু queue কাজ করছে না

### Fix

প্রতিটি capability-এর জন্য তিনটি state রাখা উচিত:

```plaintext
configuredreadyoperational
```

উদাহরণ:

```json
{  "capability": "scrape",  "configured": true,  "ready": true,  "operational": false,  "last_checked_at": "...",  "error": "..."}
```

## Priority 3 — Core-to-Worker authenticated dispatch

Worker route আছে, কিন্তু Core-to-Worker call-এ নিচের বিষয়গুলো নিশ্চিত করতে হবে:

- service-to-service authentication
- request signing অথবা internal token
- tenant/user ID propagation
- correlation ID
- idempotency key
- timeout
- retry policy
- audit log

Worker endpoint শুধু URL reachable হলেই secure ধরা যাবে না।

## Priority 4 — Task status persistence

বর্তমান task lifecycle queue/runtime state-এর ওপর নির্ভরশীল।

Production-ready করতে task status persistent store-এ রাখা উচিত:

```plaintext
queuedrunningcompletedfailedcancelledexpired
```

প্রতিটি task-এ থাকা উচিত:

```plaintext
task_idtenant_iduser_idcapabilitycreated_atstarted_atcompleted_atretry_countresult_referenceerror_codecorrelation_id
```

Memory-only status হলে Worker restart-এর পর task status হারিয়ে যেতে পারে।

## Priority 7 — Async Supabase calls

`docs/ADMIN_TASKS.md`-এ গুরুত্বপূর্ণ সমস্যা উল্লেখ আছে:

```plaintext
async route-এর ভিতরে synchronous Supabase execute()
```

এটি event loop block করতে পারে।

### Fix options

একটি বেছে নিতে হবে:

1. Supabase async client ব্যবহার করা
2. Sync DB call `asyncio.to_thread()`-এর মধ্যে চালানো
3. Database access layer-কে সম্পূর্ণ async করা

এটি বিশেষ করে high-traffic route এবং health route-এ গুরুত্বপূর্ণ।
