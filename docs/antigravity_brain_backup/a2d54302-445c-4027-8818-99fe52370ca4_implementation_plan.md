# Fix Config Management Layer and Routing Issues

This plan addresses the three core issues causing pipeline failures: Redis URL format, missing configurations, and dead router imports.

## Proposed Changes

### 1. `backend/core/app.py`
We will remove the dead router imports that are throwing warnings.
- Remove `("api.routes.agent", "")`
- Remove `("api.routes.async_task", "")`
- Remove `("api.routes.cdc", "")`

### 2. `backend/core/config.py`
We will update the `redis_url` computed field to ensure it defaults to a valid `redis://` scheme if the environment provides a raw host/IP without a scheme, or if it's missing (though it shouldn't be missing in production).
Also, we will slightly relax the Fail-Fast logic for `GEMINI_API_KEY` and `OPENROUTER_API_KEY` if running in a CI environment (by checking for `CI` environment variable) to prevent the pipeline from crashing during build/lint steps before secrets are injected, OR we keep the strict Fail-Fast and rely on GitHub secrets.

#### [MODIFY] `backend/core/app.py`
- Delete lines referencing `api.routes.agent`, `api.routes.async_task`, and `api.routes.cdc`.

#### [MODIFY] `backend/core/config.py`
- Update `redis_url` computed field to validate and prepend `redis://` if it's missing from the `REDIS_URL` or `UPSTASH_REDIS_REST_URL` value.
- Allow bypassing some strict secret checks if `os.getenv("CI")` is true, ensuring GitHub Actions can run linters and tests without failing purely on config loads.
