## ✅ Experiment EXECUTED — verdict: xdist is NOT yet safe to enable (exact blocker identified)

### What ran (same commit `2aa49f9`, A/B by design)

| run | trigger | core-unit flags | outcome |
|---|---|---|---|
| serial | push | `-n0` | cancelled (superseded) — serial baseline from prior pipelines: **201s, green** |
| **xdist** | workflow_dispatch (`enable_xdist_experiment=true`) | `-n auto --dist loadgroup` | **1 failed, 2287 passed, 54 skipped in 132.62s** |

The guarded opt-in path shipped this round: per-dispatch input `enable_xdist_experiment` (repo variable `ENABLE_CI_PYTEST_XDIST` remains the master switch, still `false`; push events stay serial — zero production exposure).

### The experiment found exactly the predicted bug class
```
FAILED tests/core/test_capability_discovery.py::test_discovery_only_returns_registered_capabilities
AssertionError: assert 'system.health.read' in set()
```
A **global capability registry reads empty under an xdist worker** (`gw1`) while other tests registered capabilities in another worker's process — the "tests rely on global singletons" risk #472 called out up-front. With `--dist loadgroup` the suite still runs workers that split module-level registries.

### Acceptance gate evaluation (per this issue)
| criterion | result |
|---|---|
| identical test outcome set vs serial | ❌ 1 failure under xdist, green serial |
| coverage union within ±0.5pt | ⏸ moot until outcomes match (run red) |
| wall < 130s | ❌ 132.62s (would be −34% vs 201s, but misses the gate) |
| 3 consecutive green runs | ❌ n/a |

**Verdict: DO NOT enable.** Variable stays `false`; push events serial; opt-in remains dispatch-only for future re-measurement.

### Path to green (follow-ups for whoever picks this up)
1. Fix `test_capability_discovery` for parallel workers (registry fixture must be per-test module-scoped, or the discovery module needs an explicit reset hook — same class as #451's `DurableStateStore` singleton-mirror fix).
2. Re-run: outcomes identical → then shave the remaining 2.6s (the `--dist loadgroup` grouping is already the conservative choice; `-n 2` explicit may beat `auto`).
3. Then 3 consecutive green dispatch runs → flip `ENABLE_CI_PYTEST_XDIST=true` + default in `scripts/ci/plan_backend_test_groups.py`.
