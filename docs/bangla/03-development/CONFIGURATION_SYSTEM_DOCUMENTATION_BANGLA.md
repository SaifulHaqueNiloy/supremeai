# SupremeAI 2.0 কনফিগারেশন সিস্টেম ডকুমেন্টেশন

## ১. পরিচিতি

SupremeAI ২.০ প্রকল্পের কনফিগারেশন ম্যানেজমেন্ট সিস্টেমের বিস্তারিত ডকুমেন্টেশন। এই ডকুমেন্ট কনফিগারেশন ফাইলগুলো, তাদের কাজ, এবং কীভাবে সেগুলো পরস্পরের সাথে সম্পর্কিত সে সম্পর্কে বিস্তারিত তথ্য দেয়।

## ২. কনফিগারেশন ফাইল ম্যাপিং

### ২.১ প্রধান কনফিগারেশন ফাইলগুলো

| ফাইল | অবস্থান | কাজ | ব্যবহার |
|-------|---------|-----|--------|
| config.py | backend/core/config.py | প্রধান কনফিগারেশন মডেল | অ্যাপ্লিকেশন স্টার্টআপে সব সেটিংস লোড করে |
| config.py | backend/api/routes/config.py | রানটাইম কনফিগারেশন এপিআই | ডাইনামিক কনফিগারেশন পরিবর্তনের জন্য |
| render.yaml | root directory | ডেপ্লয়মেন্ট কনফিগারেশন | বিভিন্ন সার্ভিসের এনভায়রনমেন্ট ভ্যারিয়েবল সেট করে |
| Dockerfile | root directory | কনটেইনার কনফিগারেশন | বিল্ড এবং রানটাইম সেটিংস নির্ধারণ করে |

### ২.২ কনফিগারেশন লোডিং প্রক্রিয়া

1. **স্টার্টআপ সময়ে** - `backend/core/config.py` থেকে সব কনফিগারেশন লোড হয়
2. **রানটাইমে** - `backend/api/routes/config.py` এর মাধ্যমে কিছু কনফিগারেশন ডাইনামিক্যালি পরিবর্তন করা যায়
3. **ডেপ্লয়মেন্টে** - `render.yaml` এর মাধ্যমে এনভায়রনমেন্ট স্পেসিফিক সেটিংস সেট হয়

## ৩. কনফিগারেশন ভ্যালিডেশন সিস্টেম

### ৩.১ কনফিগারেশন ভ্যালিডেশন প্রক্রিয়া

প্রতিটি কনফিগারেশন লোড হওয়ার সময় নিম্নলিখিত ভ্যালিডেশন প্রক্রিয়া চলে:

1. এনভায়রনমেন্ট ভ্যারিয়েবল চেক করা
2. ডিফল্ট ভ্যালু সেট করা
3. টাইপ চেক করা
4. সুরক্ষা চেক করা

### ৩.২ ভ্যালিডেশন উদাহরণ

```python
@validator("env")
def validate_env(cls, value: str) -> str:
    allowed = {"local", "staging", "production", "test"}
    if value.lower() not in allowed:
        raise ValueError(f"ENV must be one of {allowed}, got '{value}'")
    return value.lower()
```

## ৪. CORS কনফিগারেশন

### ৪.১ বিভিন্ন সার্ভিসের জন্য CORS

- **User API** (`app_user.py`): শুধুমাত্র ইউজার ক্লায়েন্টের জন্য অনুমতি
- **Admin API** (`app_admin.py`): শুধুমাত্র অ্যাডমিন কনসোলের জন্য অনুমতি
- **Common CORS** (`app_builder.py`): সাধারণ সেটিংস যা সব সার্ভিসে প্রযোজ্য

### ৪.২ CORS ভ্যালিডেশন

প্রোডাকশনে কোনো wildcard (*) অনুমতি নেই, সব অরিজিন স্পেসিফিক হতে হবে।

## ৫. সিকিউরিটি কনফিগারেশন

### ৫.১ মিডলওয়্যার অর্ডার

মিডলওয়্যারগুলো নিরাপত্তা অনুসারে সাজানো হয়েছে:

1. RequestContextMiddleware
2. GZipMiddleware
3. RequestIdMiddleware
4. TrustedOriginMiddleware
5. SupremeContextMiddleware
6. TenantExtractionMiddleware
7. ObservabilityMiddleware
8. **AuthMiddleware** (Authentication অবশ্যই আগে হবে)
9. APIKeyAuthMiddleware
10. AutonoGuardMiddleware
11. HoneypotMiddleware
12. ChaosInjectorMiddleware
13. IdempotencyMiddleware
14. CORSMiddleware
15. ResponseStandardizationMiddleware

### ৫.২ সিক্রেট ম্যানেজমেন্ট

সিক্রেটগুলো বিভিন্ন সোর্স থেকে লোড হয়:

1. এনভায়রনমেন্ট ভ্যারিয়েবল
2. গুগল ক্লাউড সিক্রেট ম্যানেজার
3. ইনফিসিক্যাল ভল্ট
4. লোকাল ফাইল (টেস্টের জন্য)

## ৬. হেল্থ চেক কনফিগারেশন

### ৬.১ কনটেইনার হেল্থ চেক

ডকারফাইলে নিম্নলিখিত হেল্থ চেক সেট করা হয়েছে:

```dockerfile
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
  CMD curl -sf http://localhost:${PORT:-8080}/health || exit 1
```

### ৬.২ অ্যাপ্লিকেশন হেল্থ এন্ডপয়েন্ট

অ্যাপ্লিকেশনের হেল্থ এন্ডপয়েন্ট রেডিস কানেকশন এবং এপিআই কী চেক করে।
